# Glyph Grid Studio v0.2 — performance & feature report

**Period:** 2026-10-17 → 2026-10-18 · **Scope:** v0.1.10 → `main` @ `c12dcf9` (PR #8) · **Log:** `BUGS_AND_ITERATIONS.md` ITER-040 … ITER-084 · **Plan / research:** `plan.md`, `research.md`

![v0.2 feature showcase: video source + palette timeline, kinetic typography, text over a source, terminal export](assets/v0.2-showcase.gif)

## Verdict

Headless renders are **~1.8× faster** (28 s → 15 s for the 120-frame benchmark), **bit-reproducible** (were 36–38 dB run-to-run noise), and default MP4s are **4.2× smaller**. The CLI/MCP surface is schema-validated end to end, and four new features shipped: terminal-native export, a keyframe timeline, kinetic typography, and video sources. The test gate grew from 24 to 49 integration checks, 10 → 34 MCP checks and 15 → 73 Rust tests.

## What we learned (the measurement that changed the plan)

v0.1.10 was planned on the reading "headless renders are idle: 2.7 s CPU against 20–56 s wall, WebKit throttles the off-screen window". That was a measurement artefact. `time` only sees the Tauri process; WebKit's `WebContent.xpc` and `GPU.xpc` are launchd children and were never counted. With them counted (ITER-045) the render was CPU-bound at normal priority: 24.5 s WebContent + 6.5 s GPU on a 28 s wall. The real costs were found and removed in order:

1. **Nondeterministic warm-up** (ITER-046): the per-cell EMA depended on how many live draws ran before frame 0. Priming it with 11 signal-only passes made output a pure function of (source, config, seed), and made every later speedup safe to gate with byte-identity.
2. **Start-up sleeps and a stray draw** (ITER-047): 2.1 s of fixed sleeps, plus a p5 loop quirk that let one uncaptured draw through under backpressure. Wall 28.4 → 15.2 s.
3. **PNG round trip per frame** (ITER-052): headless frames now ship raw RGBA over IPC. The still-source layer memo had never hit because of a `this`-binding bug; fixed.
4. **Post-capture encode tail** (ITER-053/054): gifski now encodes while capture runs, and decode is windowed instead of all-at-once.
5. **Bloom never ran headless** (ITER-057): a one-level config merge dropped default stage params. One shared deep merge now makes CLI output match the GUI.

## What shipped

**Headless as a product (ITER-056..061, 068)** — preset JSON Schema as the single source of truth (`validate`, `render --dry-run`, schema-projected `catalog`); one deep merger for GUI/CLI/batch/MCP; `--set dotted.path=value`; `--frames auto`; MCP `glyph_grid_batch`, async tools with progress and cancel; exit codes 0/1/2/3 with `--timeout` and a stall watchdog; NDJSON `--progress`; versioned manifests with `--resume` sidecars.

**Throughput (ITER-050..055, 070)** — MP4 rate control, Twitter-fit predictor, raw-RGBA capture, streaming GIF, bounded decode-ahead, `batch --jobs N` (N=2 measured ~17 % faster on a loaded 8-core machine; N=4 oversubscribes now that renders are CPU-bound).

**GUI and GPU (ITER-062..067, 069)** — idle loop parking, vendored front-end deps, asset-protocol import with a Rust header probe, the WebGL grid path revived (silently dead since v0.1.6) and made sprite-equivalent, a WebGL2 source preprocess for the GUI (headless stays on the JS path so it remains deterministic).

**New features (ITER-073..077)**
- `GlyphFrame` IR in every drawer + a `FrameSource` adapter — the seams the features below sit on.
- **Terminal-native export:** `--format txt|ansi|cast|html` from GUI, CLI, batch and MCP, in every selection mode.
- **Keyframe timeline:** `--timeline 'palette=0:(cream-paper),1:(spice)'` on any CONFIG path, OKLab palette blends, deterministic in headless.
- **Kinetic typography:** `--text`, `--srt`/`.lrc` lyric files, typewriter/rise/fade/scale, composited over a source with `--text-blend`.
- **Video sources:** mp4/mov/webm, frame-exact H.264 decode in Rust (other codecs via the WebView), camera as beta.

**Security hardening (ITER-078..084)** — text exports confined to the job's declared path and text extensions; the camera is runtime-only state a preset can never switch on; and an adversarial pass over the MP4 demuxer/decoder closed: in-band SPS resizing, embedded start codes, coded-vs-cropped size admission, unbounded `stts`/`ctts`/`stsz`/`stsc`/`stco` tables, oversized and zero-size boxes, fragmented MP4 and `emsg` (refused), and two reproduced hangs. The final verification round reproduced nothing further.

## Not done, by decision

- **GPU-process canvas off** (private WebKit prefs): deferred — WebContent, not the GPU process, is the bottleneck.
- **WASM/SIMD** for the pixel stages: ceiling ≈ 2.4 ms/frame; not scheduled.
- **Camera** ships as beta: the macOS permission prompt needs the signed bundle, and a hardened-runtime build needs the camera entitlement.
- **Anamorphic H.264** and **fragmented MP4** are refused by the Rust decoder and fall back to the WebView `<video>` path.
- **Release:** version bump to 0.2.0, DMG, Cask and landing page are a separate release step (`RELEASING.md`).

## How it was built

Planned in one research pass (5 dimension auditors with adversarial skeptics; 27 findings confirmed, 3 refuted; 13 features ranked by two judges), then implemented in six phases. Phases 2, 3 and 4 ran in parallel in separate git worktrees and were merged with conflict resolution (ITER-071). Opus 5.5 implemented; Fable 5.1 reviewed every phase diff, and every fix pass was re-verified. Each commit passed the same gate before landing: cargo build + test, `npm test`, the full `run-all.sh`, byte-identity, and a PSNR check against the pre-change golden render.
